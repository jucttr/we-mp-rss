## 一、项目现状分析

### 1.3 现有通知推送机制

项目已支持以下通知渠道：
- ✅ 钉钉
- ✅ 企业微信
- ✅ 飞书
- ✅ 自定义 Webhook
- ✅ Bark（iOS 通知）

### 1.4 微信公众号采集流程

```
1. 搜索公众号 → mp.weixin.qq.com/cgi-bin/searchbiz
2. 添加订阅 → 存储到 Feed 表
3. 定时采集 → 调用微信公众平台文章列表 API
4. 内容解析 → 存储到 Article 表
5. 新文章发现 → 调用 Notice 模块推送
6. RSS 输出 → 定时任务调度更新
```

### 1.5 核心数据模型

**Feed 模型（订阅源）**
- `id`: 订阅源唯一标识
- `mp_name`: 名称
- `mp_cover`: 头像
- `mp_intro`: 简介
- `faker_id`: 平台原始 ID
- `status`: 状态
- `sync_time`: 同步时间
- `update_time`: 更新时间

**Article 模型（文章）**
- `id`: 文章唯一标识
- `mp_id`: 所属订阅源 ID
- `title`: 标题
- `content`: 内容
- `publish_time`: 发布时间
- `url`: 原文链接

## 三、原创内容判断逻辑（已验证）

### 3.1 接口原生支持 type=0 参数

雪球 API **原生支持** `type=0` 参数来筛选原发内容，无需二次判断。

### 3.2 type 字段说明

| type 值 | 说明 | 示例 |
|---------|------|------|
| `"0"` | 原发内容（纯文字） | 用户直接发布的帖子 |
| `"2"` | 原发内容（长文） | 用户发布的长篇文章 |

### 3.3 最终采集方案

```python
# 直接使用 type=0 参数获取原创内容
GET /v4/statuses/user_timeline.json?user_id={id}&type=0&page=1

# 返回的数据全部是原创内容，无需再判断 retweeted_status
```

## 四、雪球平台分析

### 4.1 用户页面结构

雪球用户个人主页链接格式：`https://xueqiu.com/u/{userId}`

示例：`https://xueqiu.com/u/1247347556`（大道无形我有型）

页面展示内容：
- 用户名、头像、简介
- 粉丝数、关注数
- 帖子列表（原创、评论、收藏等分类）
- 分页功能

### 4.2 核心 API 接口

#### 4.2.1 用户搜索 API（无需登录可用）

```
GET https://xueqiu.com/query/v1/search/user.json
```

**请求参数：**
- `q`: 搜索关键词
- `count`: 每页数量（建议 20）
- `page`: 页码

#### 4.2.2 用户动态 API（核心内容接口，无需登录可用）

```
GET https://xueqiu.com/v4/statuses/user_timeline.json
```

**请求参数：**
- `page`: 页码
- `user_id`: 用户 ID
- `type`: 筛选类型（`0` = 原发内容）

#### 4.2.3 其他相关 API

| API | 用途 | 登录要求 |
|-----|------|---------|
| `/v4/statuses/user_timeline.json?type=0` | 用户原发内容 | 无需登录 |
| `/query/v1/search/user.json` | 用户搜索 | 无需登录 |

### 4.4 反爬虫机制分析（简化版 - 无需登录）

#### 4.4.1 动态参数 md5__1038

所有 API 请求都携带动态生成的 `md5__1038` 参数：
- 每次请求生成不同的加密字符串
- 基于 URL、时间戳等因子生成
- 用于接口鉴权和请求完整性校验

**处理方案：** 由于无需登录，可以直接通过 Playwright 访问雪球页面，从页面环境中获取有效的 md5 参数。

#### 4.4.2 Cookie 鉴权（已简化）

由于采用无需登录方案，Cookie 要求已大幅简化：
- 无需用户登录 Cookie
- 仅需基本的浏览器标识 Cookie（如有）
- 通过 Playwright 模拟浏览器请求即可

#### 4.4.3 User-Agent 检测

需要使用真实浏览器的 User-Agent，复用项目现有的 `browser_type` 配置即可。

#### 4.4.4 IP 频率限制

雪球有请求频率限制，但用户发布动态不频繁，采集间隔可适当放宽。

## 六、反爬虫处理方案

### 6.1 方案选择：Playwright 浏览器模拟（已确认）

**确认决策：** 考虑稳定性，采用 Playwright 方案。

**优势：**
1. 绕过 md5__1038 参数校验
2. 模拟真实浏览器环境
3. 复用项目现有 Playwright 能力
4. 无需处理复杂的 Cookie 管理

### 6.2 可复用组件

| 组件 | 用途 |
|------|------|
| `driver/playwright_driver.py` | 浏览器启动和管理 |
| `driver/anti_crawler_config.py` | UA、Viewport 配置 |
| `driver/anti_crawler_behavior.js` | 行为模拟脚本 |
| `core/notice/__init__.py` | 通知推送（完全复用） |
| `jobs/notice.py` | 通知推送调度（复用） |

### 6.3 雪球采集流程设计

```
1. Playwright 打开雪球用户页面（获取 md5 参数环境）
2. 携带 md5 参数请求原发动态 API（?type=0）
3. 解析 JSON 响应（type=0 接口已过滤，无需二次判断）
4. 转换为标准 Article 格式
5. 存储到数据库
6. 检查是否有新内容 → 调用现有通知推送
7. 关闭浏览器
```

### 6.4 采集频率建议

**确认决策：** 雪球用户发布动态不频繁，采集间隔可适当放宽。

建议采集间隔：
- 快速同步：30 分钟 - 1 小时
- 正常同步：2 - 4 小时
- 保守同步：6 - 12 小时
